**Scope:** rebase of two pushed-but-unmerged branches (`feat/core-wave-125-workflow-persistence-and-ingress`, `feat/core-wave-126-node-inspector-and-execution-history`) onto main after the Wave 127/128 authentication work landed, plus one defect found during verification.

## 1. Why this was necessary

Both branches were pushed to origin with **no open PR** — invisible work. They were cut
before #491 (per-tenant RAG), #492 (versioned signatures), #494 (trigger-workflow auth)
and #495 merged, so rebasing them as-is would have silently dropped tenancy, versioned
signatures and the new authentication rules. The Continued Development Plan carried this
as an explicit open item:

> Rebase and open PRs for `feat/core-wave-125-...` and `feat/core-wave-126-...`. Both are
> pushed with no PR and both predate #491/#492, so merging them as-is would drop the
> tenancy and versioned-signature work.

## 2. Conflict resolution, by contract rather than by side

Twelve files overlapped. Each was resolved by picking whichever implementation the trunk
now owns, then re-applying the branch's actual feature on top:

### `supabase/functions/_shared/workflowAuth.ts` (add/add)
Main (#494) created `authorizeTrigger`/`TriggerCaller`/`TriggerDecision`. The branch
created a parallel auth-primitive module (`resolveWorkflowCaller`, `hmacSha256Hex`,
`isTimestampFresh`, `timingSafeEqual`, `verifySignature`, `resolveActingUserId`,
`coerceUuidOrNull`).

Resolution: keep main's contract **verbatim** so `trigger-workflow` identity binding and
its 11 tests are unchanged. Delete the branch's crypto — `edgeAuth.verifySignedRequest`
(#492) already implements HMAC-SHA256 with a 5-minute skew window and a date-keyed
dual-accept policy, so keeping both would be two implementations of the same primitive.
Keep `coerceUuidOrNull`, which fixes a real bug: `authorizeTrigger` correctly returns the
`"system"` sentinel for internal callers, but `workflow_execution_logs.user_id` is a uuid
and inserting `"system"` aborts the whole insert and loses the audit row.

### `supabase/functions/trigger-workflow/index.ts`
One classifier. A presented `X-Axim-Signature` must verify (`verifySignedRequest`, terminal
— a bad signature is never a downgrade to a weaker path); otherwise `resolveCaller`
classifies bearer service keys and dashboard JWTs. Identity binding stays
`authorizeTrigger(caller, body.userId)`. The branch's real DAG dispatch engine
(`workflowActions.ts`: `api_call`, `email`, `robot_sim_run`, `robot_policy_gate`,
`robot_ota_deploy`), execution-log write with `status`/`error_message`/`duration_ms`, and
the "no steps" / cycle / unsupported-node guards are all preserved.

### `src/services/onyxAI/commands/workflowCommands.js`
Main's `sessionAuthHeaders` browser path (the `check:creds`-clean pattern), plus the
branch's two real fixes: a `success === false` guard (a failed run no longer reports as
success in the command hub) and a step/duration summary from the now-real response.

### `tests/e2e-workflow.test.js`
Main deliberately deleted the simulated latency/throughput stubs in #490 ("49 stub
tests deleted"). The branch only touched one assertion inside a deleted stub, so the
deletion is preserved rather than resurrected.

### `tests/workflow-auth.test.js`
Main's 11 `authorizeTrigger` tests are kept; 6 new tests cover `coerceUuidOrNull`.

### `cloud/package.json`, `cloud/package-lock.json`
The branch's dependency CVE patch (commit `3d03da7`) is byte-identical to `265d611`
already on main, so it is dropped.

### Docs (`AGENTS_VERIFICATION.md`, `CHANGELOG.md`, `DEBUGGING_NOTES.md`)
Main's versions are the base; this appendix and the new CHANGELOG entry below replace
the branch's inline edits, per the one-file-per-change rule.

## 3. Defect found and fixed during verification

`WorkflowBuilder.test.jsx` > `action node configuration` — under a 2-vCPU sandbox with a
workspace-sync daemon running, individual heavy click → inspector → run/save round-trips
exceeded vitest's 5s default and timed out, although the component behaved correctly
(verified by passing with a raised timeout; ~1–2s on CI hardware). The 30s timeout is
scoped to that describe block so a genuinely-hung render still fails. This is the same
class of environmental flake the branch already fixed elsewhere: the deterministic
concurrency assertion in the e2e burst test and the `NODE_ENV: 'test'` pin in
`vitest.config.js` (which stops an ambient `NODE_ENV=production` from resolving React's
production build and breaking every `act()` call).
